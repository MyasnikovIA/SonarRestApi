# Эндпоинты API для работы с исходным кодом

В ходе доработки сервера были добавлены новые эндпоинты для получения полного листинга кода файлов из SonarQube. Это позволяет получать контекст не только вокруг конкретной ошибки, но и весь файл целиком.

---

## 1. Получение сырого JSON от SonarQube

**`GET /api/sources`**

Прокси-эндпоинт, который напрямую перенаправляет запрос к API SonarQube `/api/sources/lines`. Возвращает исходный JSON-ответ от SonarQube без изменений.

### Параметры (Query):
| Параметр | Обязательный | По умолчанию | Описание |
| :--- | :---: | :--- | :--- |
| `key` | **Да** | — | Полный ключ компонента (например, `MEDMIS-tMIS.mis:Cache/FileCache.inc`) |
| `from` | Нет | `1` | Начальная строка |
| `to` | Нет | `100000` | Конечная строка |

### Пример запроса:
```http
GET http://localhost:6060/api/sources?key=MEDMIS-tMIS.mis%3ACache%2FFileCache.inc&from=1&to=130
```

### Пример ответа:
Возвращается сырой JSON от SonarQube (массив `sources` с полями `line`, `code`, `scmAuthor` и т.д.).

## 2. Получение объединенного листинга файла

**`GET /api/sources/full`**

Этот эндпоинт запрашивает строки кода у SonarQube и склеивает их в один непрерывный текст. Он поддерживает несколько форматов вывода: чистый JSON (по умолчанию), обычный текст (TXT) и HTML с подсветкой синтаксиса.

### Параметры (Query):
| Параметр | Обязательный | По умолчанию | Описание |
| :--- | :---: | :--- | :--- |
| `key` | **Да** | — | Полный ключ компонента (например, `MEDMIS-tMIS.mis:Cache/FileCache.inc`) |
| `from` | Нет | `1` | Начальная строка |
| `to` | Нет | `100000` | Конечная строка |
| `format` | Нет | `json` | Формат ответа: `json`, `txt` или `html` |

### Режимы ответа:

#### 2.1. Формат `json` (по умолчанию)
Возвращает JSON-объект, в поле `code` которого лежит чистый текст (без HTML-тегов и сущностей).

*Пример запроса:*
```http
GET http://localhost:6060/api/sources/full?key=MEDMIS-tMIS.mis%3ACache%2FFileCache.inc
```
*Пример ответа:*
```json
{
  "key": "MEDMIS-tMIS.mis:Cache/FileCache.inc",
  "format": "json",
  "code": "<?php\n\nclass FileCache\n{\n\n    /**\n     * The root cache directory.\n     * @var string\n     */\n    private $cache_dir;\n...",
  "linesCount": 130
}
```

#### 2.2. Формат `txt`
Возвращает ответ с `Content-Type: text/plain; charset=utf-8`. Это чистый текст файла, который можно легко скачать или скопировать.

*Пример запроса:*
```http
GET http://localhost:6060/api/sources/full?key=MEDMIS-tMIS.mis%3ACache%2FFileCache.inc&format=txt
```

#### 2.3. Формат `html`
Возвращает ответ с `Content-Type: text/html; charset=utf-8`. Сервер генерирует полноценную HTML-страницу с тегом `<pre><code>`, сохраняя оригинальные CSS-классы SonarQube (`<span class="k">`, `<span class="s">` и т.д.) и добавляя базовые стили для темной темы, чтобы подсветка синтаксиса отображалась в браузере.

*Пример запроса:*
```http
GET http://localhost:6060/api/sources/full?key=MEDMIS-tMIS.mis%3ACache%2FFileCache.inc&format=html
```

## 3. Изменения в существующем эндпоинте генерации промптов

**`GET /api/prompt/build`**

Для улучшения качества ответов LLM, в эндпоинт генерации промптов было добавлено автоматическое обогащение контекстом.

Если промпт формируется для **одного конкретного issue** (передан параметр `issueKey`), сервер теперь автоматически:
1. Запрашивает полный код файла (используя логику `/api/sources/full`).
2. Подставляет код в параметр `[FULL_FILE_CODE]` (если он есть в шаблоне `prompts/*.txt`).
3. Если тега `[FULL_FILE_CODE]` в шаблоне нет, сервер **принудительно добавляет** полный листинг в самый конец промпта, оборачивая его в Markdown-блок кода с правильным указанием языка:
   ```markdown
   === ПОЛНЫЙ ЛИСТИНГ ФАЙЛА ===
   <?php
   // ... весь код файла ...
   ```
   *(Сервер также автоматически закрывает `` ``` `` предыдущего блока кода, если шаблон промпта этого не сделал).*
