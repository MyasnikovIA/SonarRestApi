Ты — опытный разработчик и эксперт по статическому анализу кода (SonarQube).
Проанализируй замечание, найденное анализатором, и дай структурированный ответ.

=== ДЕТАЛИ ЗАМЕЧАНИЯ ===

- Правило: [RULE_KEY] — [RULE_NAME]
- Сообщение анализатора: [MESSAGE]
- Критичность (Severity): [SEVERITY]
- Файл: [LOCATION]
- Язык: [LANGUAGE]

=== ФРАГМЕНТ КОДА ===

```[LANGUAGE_FENCE]
[CODE]
```

Маркеры >>> и <<< в коде показывают конкретное место, на которое указал анализатор.

=== ЗАДАНИЕ ===

Дай ответ строго по пунктам 1–4 ниже. Пиши по-русски, без markdown-разметки
(без **, __, ###), обычным текстом с нумерацией.

1. СУТЬ ПРОБЛЕМЫ
   Объясни в 2–4 предложениях, почему данная конструкция считается ошибочной
   или опасной. Приведи конкретный сценарий: при каких входных данных или
   условиях код поведёт себя неправильно.

2. КЛАССИФИКАЦИЯ
   Определи, к какому из трёх классов относится замечание:

   A) РЕАЛЬНЫЙ ДЕФЕКТ — код ведёт себя не так, как задумано, или может
      привести к сбою, потере данных, уязвимости. Признаки:
      - логическая ошибка, недостижимый код (dead-code);
      - сравнение с заведомо невозможным значением (count($x) < 0,
        strlen() < 0, size() < 0, index < 0 для неотрицательного индекса);
      - разыменование null без проверки, где по контракту null недопустим;
      - перепутаны == и =, инвертировано условие, неверный знак сравнения
        (< вместо >, <= вместо <) в валидации входных данных;
      - off-by-one в индексах или срезах;
      - потеря или перезапись данных без сохранения;
      - утечка ресурса, небезопасный парсинг пользовательского ввода;
      - неверный тип поля в публичном контракте относительно OpenAPI-спеки.

   B) СТИЛИСТИКА / СТРУКТУРА — поведение кода НЕ меняется, замечание
      касается формы, а не сути. Признаки:
      - использование строк вместо констант (magic strings, string literals);
      - дублирование одинаковых строковых литералов;
      - magic numbers (кроме случаев, когда число — часть бизнес-логики);
      - naming (camelCase/snake_case), отступы, порядок импортов;
      - отсутствие Javadoc/PHPDoc у публичных методов;
      - длина метода, вложенность, число параметров;
      - "unused import";
      - отсутствие default в switch, если switch покрывает enum полностью;
      - дублирование кода (одинаковые case в разных ветках).

   ВАЖНО: строки вместо констант — это ВСЕГДА стилистика, а не дефект.
   Строковый литерал "GET", "POST", "application/json", "/api/users",
   "401", "422" на месте константы НЕ ЛОМАЕТ поведение кода.
   SonarQube-правила "String literals should not be duplicated",
   "Magic strings should be constants", "Define a constant instead of
   duplicating this literal" — все относятся к классу B.
   Не выдавай такие замечания за реальные ошибки.

   C) FALSE POSITIVE — анализатор ошибся, проблемы нет. Код корректен,
      но правило сработало из-за особенностей анализа (например, динамическая
      типизация, параметризованный SQL, рефлексия).

3. КРИТИЧНОСТЬ
   Оцени реальную серьезность замечания в контексте данного кода:
   - "подтверждаю" — Severity [SEVERITY] адекватна;
   - "завышена" — реальная серьезность ниже, чем указал анализатор;
   - "занижена" — реальная серьезность выше.
   Обоснуй в 1–2 предложениях.

4. ИСПРАВЛЕНИЕ
   - Если класс A (РЕАЛЬНЫЙ ДЕФЕКТ): предложи исправленный вариант кода.
     Покажи, что было и что стало. Объясни изменения комментариями.
   - Если класс B (СТИЛИСТИКА): объясни, стоит ли вообще править. Если код
     генерируется автоматически (OpenAPI, protobuf, ORM) — правки затрутся
     при следующей регенерации, исправлять не нужно. Если код ручной —
     предложи, как вынести в константу, и покажи пример.
   - Если класс C (FALSE POSITIVE): объясни, почему анализатор ошибся.
     Если возможно — предложи, что сделать, чтобы анализатор больше
     не срабатывал (аннотация @SuppressWarnings, комментарий-обоснование,
     настройка Quality Profile).

=== ТРЕБОВАНИЯ К ОТВЕТУ ===

- Пиши по-русски, обычным текстом, без markdown-разметки.
- Ответ структурируй ровно по четырём пунктам: 1, 2, 3, 4.
- Будь конкретен: ссылайся на реальные строки и переменные из фрагмента кода.
- Не выдумывай контекст, которого нет в коде. Если для вывода не хватает
  информации — так и напиши в пункте 2 ("требует уточнения контракта").
- Для класса A обязательно покажи исправленный код.
- Для класса B не предлагай исправлений, если код сгенерирован.
- Объём: 15–40 строк.
```

## Что подставит сервер

| Тэг | Значение |
|---|---|
| `[RULE_KEY]` | ключ правила SonarQube (`php:S1192`, `java:S2583`, …) |
| `[RULE_NAME]` | человекочитаемое имя правила (`fetchRuleName`) |
| `[MESSAGE]` | текст сообщения анализатора |
| `[SEVERITY]` | `impactSeverity` или `severity` (`HIGH`, `MEDIUM`, `LOW`, …) |
| `[LOCATION]` | `component:line` (например, `src/Model/User.php:42`) |
| `[LANGUAGE]` | язык (`PHP`, `Java`, `TypeScript`, …) |
| `[LANGUAGE_FENCE]` | маркер для ` ``` ` (`php`, `java`, `typescript`, …) |
| `[CODE]` | фрагмент кода с маркерами `>>>` / `<<<` вокруг проблемной строки |

Ни `[STATUS]`, ни `[TAGS_LIST]` здесь не используются — этот промпт не выбирает статус/теги, а только анализирует.

## Проверка

1. **Сохраните файл** в `C:\JavaProject\SonarRestApi_git\prompts\analyze-issue.txt`.
2. **Перезапустите JVM.**
3. **В логе старта:**
   ```
   [ApiServer] available prompts: analyze-issue, auto-resolve, bulk-status-comment, status-comment
   ```
4. **Из консоли браузера:**
   ```
   fetch('/api/prompt/build?project=TEST&name=analyze-issue&issueKey=TEST-1')
     .then(r => r.json()).then(d => {
       console.log('len =', d.promptLength);
       console.log('has classification:', d.prompt.includes('КЛАССИФИКАЦИЯ'));
       console.log('has code markers:', d.prompt.includes('>>>'));
       console.log('has magic strings rule:', d.prompt.includes('строки вместо констант'));
     })
   ```
   Ожидается `promptLength` ~2500–3500, все три `has ... : true`.
5. **В UI** — ПКМ по issue → **📝 Сгенерировать промпт** → откроется модалка с готовым текстом, уже скопированным в буфер обмена. Вставляете в ChatGPT/Claude — получаете структурированный анализ по 4 пунктам.
